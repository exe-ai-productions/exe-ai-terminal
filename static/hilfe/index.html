Exe AI Terminal

Your own interface to language models — the ones running on this machine and the ones you rent. Chats, working folders, tools, skills and agents, all under your own roof.

1 · Chatting

Type into the field at the bottom and press Enter. While the model works, the terminal mark draws itself; models that think first show their reasoning under a collapsible row — that is display only and never sent back.

  • New chat: the button at the foot of the sidebar, the Chat menu, or ⌘N.
  • Find a chat: the search field in the sidebar, or ⌘K.
  • Manage a chat: right-click its row — pin, rename, delete. Hovering a row shows the pin directly.
  • Hide the sidebar: ⌘B, or grab the seam between sidebar and chat.
  • Under your own bubble: a copy button, and on your last question a send again arrow — it replaces the last answer, or fetches a missing one after a stop.
  • All chats live on the server, in the terminal's own database. Your browser only keeps per-device preferences: theme, language, last model.

2 · Models

The current model stands at the foot of the sidebar. Click it for a quick list of everything reachable right now; the menu bar has the full picture under Local and Cloud.

The split is not cosmetic. Local means the model runs on this machine and nothing you type leaves it. Cloud means a paid service, and your text travels there. The list only ever offers what is actually reachable — the terminal keeps checking, and model names come from the servers themselves, never from a list somebody maintained by hand.

Sampling controls — temperature, top-p, response length — sit next to the picker, and only the dials your model's server really understands are shown. What you set there becomes that model's default; a single chat can override it without disturbing the rest.

The bar at the foot of the sidebar shows how full the context window is. The small pill next to the send button fills with the live speed while an answer streams; the exact number stands under every reply.

Getting a model

Under Local → Get a model there are four steps, by how much memory your machine has, with a suggestion in each. One button fetches it; a bar shows how far it has come. Nothing to install, nothing to type.

Under Local → Model server it starts. Everything that decides how it behaves stands there as a field with a sentence beside it: how much it remembers, how much of it sits on the graphics card, which port it answers on. If a start goes wrong, the log unfolds underneath and says why.

The program needs llama-server for this — a small free program that does the actual computing. If it is missing, the window says so instead of pretending.

Cloud providers

Under Cloud a tile adds one: Anthropic, OpenAI, or an endpoint of your own if it speaks the OpenAI protocol. You paste the key once. It stays on this machine in a file only the service reads, and it is never shown again — the window only ever tells you whether one is there. Once the provider answers, its models appear by themselves.

3 · Working folders

A chat can be given up to four folders to work in. Until you share one, the assistant cannot touch a single file — there is nothing for it to reach into.

Share one from the row above the input field: pick it in a window, or paste a path. In Finder, select the folder and press ⌥⌘C.

Sharing a folder is the permission. Inside it, the assistant creates, changes, moves and deletes without asking again — that is what sharing means, and it is why nothing is shared by default. Reaching outside the shared folders is the one thing in this whole program that stops and asks you first.

Say which folder you mean by name and the assistant knows which one you are talking about; all shared folders are named to it, not just the first.

4 · What the assistant knows about you

Three layers travel with every request, and they are stacked deliberately.

layerwho writes itwhat it says
Operating instructionsthe programhow this machine works — always along, not editable
Instructionsyouwho the assistant is and how it works for you
Memorythe assistant and youwhat it has learned about you

Both editable ones live under Settings → Behaviour, and both ship empty.

Instructions

Character, tone, standing rules. One text, valid in every chat. A single chat can go without it: the switch at the bottom of that page suspends your instructions for the current chat — never the operating instructions, which describe what the machine does rather than what you prefer.

Memory

The assistant writes down what should still hold next week: how you want to be worked with, what you prefer, how your project fits together. It appears as two lists — rules that always apply, and facts that apply where they fit.

You can read and edit all of it, and clear it in one click. Two switches decide where it travels: local models get it by default, cloud models do not — a memory rides along with every request, and on your own machine that costs nothing while at a provider it means a lasting profile on someone else's server.

5 · Skills

A skill is a written-down way of doing something — a handover, a picture brief, a clear-out — that the assistant follows when it applies. Unlike a tool, you do not have to program anything: a skill is text.

Two ways to use one. Type / as the first character in the input field and a list opens; keep typing to filter, arrows to walk, Enter to pick, then write your request behind it. Or simply ask for the thing — the assistant recognises which skill fits and reaches for it.

Under Settings → Behaviour → Skills you see every skill and decide, one by one, whether the assistant may reach for it on its own. Everything it may reach for costs a little of every request; typing a name costs nothing and always works, which is why that way can never be switched off.

The assistant can also write skills for you. Describe how you want something done and ask it to keep that — it lands in the list, and you can switch it off or throw it away whenever you like. Skills that came with the program carry a note when you have changed them, and one click puts the shipped version back.

6 · Tools

Tools are what the assistant can actually do: run a command, search the web, write into your notes. Tools in the menu bar lists everything available and lets you switch each one on or off.

That switch is worth more than it looks. Every tool explains itself to the model on every single request, and with a model running on your own machine that is easily the largest part of the wait before the first word appears. Switching off what you do not need in this chat is the difference between comfortable and slow.

Shell

The built-in tool. It runs commands in your shared working folders — creating, reading, moving, renaming, deleting, opening something in Finder. Three things worth knowing:

  • Nothing is interactive. A command that waits for input hangs until it is stopped, so anything long-running belongs in the background.
  • A few commands are refused outright — sudo, wiping a disk, piping something off the net straight into a shell. That is not a question you can answer with yes.
  • Reaching outside your shared folders stops and asks. It is the only thing in the program that does.

Web search

Exe Web Search is on from the first start. Nothing to install, no account, no key. When a question needs something current — or something that happened after the model finished learning — the assistant searches, picks what looks useful, and reads those pages before answering.

It asks several search engines at once, so one going quiet does not end the search. All of them can refuse when they are asked too often; the assistant then says the search failed rather than answering as if the web were empty. At the pace of one person typing, that is rare.

Reading a page only ever reaches out to the open internet. Addresses that point back at your own machine or your own network are refused, whoever asks for them.

Servers

Everything beyond the shell comes from servers you connect under Settings → Connections → Servers: a tile per server, on or off, with sign-in where it is needed. Secrets never appear here — the file holds only the name of an entry in the server's .env, and a small lamp says whether it is set or missing. Saving applies at once; runs already going finish with the old set.

7 · Inside a reply

When the assistant uses a tool, the call appears as its own quiet row between your question and the answer. The sign in front says what kind of tool ran, and it draws itself while the call is running, then stands still. Click the row to unfold the exact arguments and the raw result.

If it writes an interim note and keeps working, the working mark returns beneath the text until the answer really ends. The numbers under a reply cover all rounds — the duration is the whole run, not the last stretch.

One question, and only one. A shell command that wants to work outside your shared folders opens a box showing exactly what it intends to run. Nothing happens before you agree. Everything else runs through — not out of carelessness, but because a question that comes ten times an hour gets clicked away unread, and then the one that matters goes with it. What stands in its place: everything else the assistant does is visible and reversible — a memory line, a written skill, a switched-on skill all sit in a window and are gone in one click. A command that has already run is not.

8 · Files the assistant makes

Ask for a web page, a table, some notes or a piece of configuration and the answer does not arrive as a wall of source. It arrives as a file box: a name, what kind of file it is, and how much it weighs. Click it and the file opens in a window of its own.

How it is shown depends on what it is. A web page or a drawing is drawn, a table becomes rows and columns you can read, everything else is shown as plain text. Where both readings make sense, Source switches between them — and where they do not, the button is simply not there.

  • Download puts the file wherever your browser keeps downloads.
  • Save to folder writes it into one of your working folders. It stays greyed out until you have released one, because there is nowhere to write it before that.
  • Print / PDF shows up for pages that are drawn. It opens your own print dialog, and every system offers “save as PDF” there.

A page written by the assistant runs sealed off inside that window. It may move and calculate, but it cannot reach the program around it — which is why you can open one without wondering what it does.

9 · Attachments and image mode

The plus button in the input bar opens a small menu; you can also drop a file anywhere on the window, or paste an image.

  • Attach image — for models that can see. The picture travels inside your bubble in a frame of its own, with two small marks in its lower corners: save on the left, enlarge on the right. Models without vision grey the entry out.
  • Attach document — PDF, TXT or MD, for any model. The text is read out of the file on the server, so nothing leaves your machine, and it stays available for the whole conversation. Very long documents are cut, and the bubble says so; a scan without a text layer is refused rather than silently sent as nothing.
  • Image mode — your text goes as a raw prompt to an image generator. While it paints, the send arrow becomes a stop button that really interrupts it.

10 · Agents and tasks

A chat is a conversation; an agent is a worker you send off. It starts with an empty head, does its job, and hands back a report — which is why an agent cannot summarise a conversation it was never part of. That kind of thing is a skill.

An agent is one Markdown file: a header between two --- lines, then its instructions. That file is the whole agent — no hidden state.

# the file name is the agent's name
---
model:                 # which model; empty = chosen when the task starts
tools:                 # only these run, and without asking
  - web_search
max_rounds: 30         # tool rounds before the run ends
max_minutes: 20        # minutes before the run ends
schedule: "08:00"      # optional daily alarm — quotes required!
schedule_task: "Collect today's headlines."
---

You are a concise researcher. …
  • Start a task: sidebar → Agents → the start button. Pick an agent, a model, write the assignment. The run continues even if you close the browser.
  • The task card shows the state, every step including each tool call, and the final report. A yellow banner means the agent is waiting for an answer from you.
  • Alarm: with schedule and schedule_task set, the agent runs daily. A missed slot is caught up once; if the previous run is still going, the slot is skipped; after three failures in a row the alarm rests until a run succeeds.
  • Mind the trap: schedule: 12:00 without quotes is read as a number. Always write it in quotes.

11 · Appearance, language, installing

  • Settings → Appearance: light, dark or follow the device; speech bubbles filled or as an outline; and the display language, per device.
  • Settings → Files: the configuration and your credentials, in plain text, for when something needs changing by hand.
  • Install as an app: open the terminal over HTTPS and use your browser's “Install” or “Add to Home Screen”. It works on phone and tablet.

12 · Two principles behind all of this

Everything arrives switched on. Anything the assistant can do by itself is on when you first open the program, and every one of those has a switch in its own menu. A feature nobody finds is a feature nobody has — so the program starts by trusting you with all of it, and gets out of the way when you say so.

One question, not ten. There is exactly one thing that stops and asks: a command reaching outside the folders you shared. Everything else runs, and everything else can be undone by looking at it. That is a deliberate trade, and it is the reason the one question is still worth reading when it appears.
